# S6: Cunningham's round-robin rule with the index order

Status: UNDER TEST (2026-10-15 12:50Z); expected to die by relabelling (see assumption A1).

## The rule, exactly
Valuations as in S1. Fixed cyclic order on Even's edges: (v, w) ascending lexicographically by vertex index. Memory: the
last edge switched. Each iteration switches the first improving edge after the last one in the cyclic order (Avis-Friedmann
arXiv 1305.3944 Algorithm 2 with ≺ = index order and initial edge (-1, -1)). Start: best-reward. `Engine.rule_cunningham`.

## Cost per iteration at bit cost
One valuation plus O(m) comparisons. Polynomial. Memory O(log m) bits.

## Why it should be outside the barriers, before testing
- B8 (Cunningham): Avis-Friedmann Theorem 4 is for "the ordering (1)" of their game G_n, and they note (p.10-11) that the
  behaviour "highly depends on the ordering used". The index order is one fixed ordering.
- B9 (DLMM Thm 4.3): the rule is index-based with m memory states (the last edge), i.e. Θ(m), not o(m/log m); DLMM's
  Observation 4.1 says n memory states suffice for a (non-uniform) linear-time rule, so the theorem's memory bound is
  essential and S6 sits just outside it.
- Gate relabelling does not apply (no levels are read).

## Unproven assumptions, named
- A1: the index order cannot realise Avis-Friedmann's ordering (1) after subdividing every Even edge by a fresh vertex
  (which makes the edge order the vertex order of the fresh vertices, i.e. arbitrary). L-SI expects A1 to be FALSE: the
  PGSolver generator cunninghamexp.ml fixes the vertex numbering (mapindex) for exactly this purpose and is being ported
  (experiments/si/gens.py cunninghamexp).

## Kill criteria
As S5.

## Adversary-controlled numbering (Lead 12:03Z): precise statement (L-SI, 13:10Z)
The rule's cyclic order is lexicographic in (v, w): for every Even vertex v its edges are CONTIGUOUS in the cycle, in
successor-index order. A renumbering of the vertices permutes the blocks and the order inside each block, nothing else.
PGSolver's lower-bound ordering for cunninghamexp (switch_cunningham.ml compare_exp; L-SI port si.py set_lower_bound_order)
is not of this form: for N = 3 the two edges of e0 are at positions 1 and 16 of 22, and the same holds for every
CycleNodePaced e_i (its x-edge is in the first class, its p-edge in a later one). So no numbering makes S6 run PGSolver's
lower-bound round-robin on this family; S6 is linear on it (3N - 3) while the lower-bound ordering gives 7, 38, 121, 324,
799, 1882, 4309, 9680, 21451 for N = 2..10.
Why L-SI cannot claim immunity: (i) a relay gadget cannot split one vertex's two edges into two positions without changing
the improvement structure (a relay vertex adds either a path element or a length and is then preferred once and for all,
after which the choice simply moves to the relay), so contiguity is a real constraint on constructions that reuse
PGSolver's family; but (ii) DLMM 2512.16684 Thm 4.3 shows that index-based rules with o(m/log m) memory have families for
EVERY index assignment, and Cunningham's rule is index-based with m memory states, just outside the theorem; a contiguity-
respecting construction for the round-robin rule is not excluded by anything L-SI knows. STATUS: not covered by a
published bound (Avis-Friedmann Thm 4 fixes "the ordering (1)" of their G_n; PGSolver's family needs a non-contiguous
order); immunity NOT argued.
