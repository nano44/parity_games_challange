# S7: most-improved single switch (count of vertices whose valuation strictly improves), invariant tie-break

Status: UNDER TEST (2026-10-15 13:35Z). Designed after the Lead's 12:12Z brief: defence against BOTH known attacks stated
before testing. It is the "most-improved" variant first listed in S3.md, now with an isomorphism-invariant tie-break.

## The rule, exactly
Valuations as in S1 (Friedmann 1106.0778 section 3). For every improving edge e = (v, w) of σ compute Ξ_{σ[e]} and
  count(e) = |{x ∈ V : Ξ_{σ[e]}(x) ≻ Ξ_σ(x)}|.
Switch an e of maximal count; ties: the e with the ≻-largest Ξ_{σ[e]}(v); remaining ties (equal count and equal new
valuation at v): smallest (v, w) by index, and the engine counts how often this last resort fires.
Deterministic, memoryless. Start: best-reward. Implementation: `vjfast most-improved` (C++), `Engine.rule_most_improved`
(Python, index tie-break only; the C++ one is the candidate).

## Cost per iteration at bit cost
|improving edges| ≤ m valuations, each O(n^2 m) word operations: O(n^2 m^2) per iteration; counts are O(log n)-bit.
Polynomial. (The most expensive rule in this lane; the C++ engine does gated_switchbestexp N = 6, n = 568, in minutes.)

## Defence against the two known attacks (stated before testing)
(i) Gate relabelling (L-RED's Gate Lemma, docs/red/R1-MSF.md): the rule is not a function of the first-difference
    position of the two valuations, nor of any function of the pair (Ξ(w), Ξ(σ(v))) alone: count(e) depends on how many
    vertices' optimal-counterstrategy plays pass through v and change. A gate (relay d_v with Odd gates e_{v,w}) adds the
    same relay to every choice of v, so it does not separate v's edges, and it shifts counts of different vertices by at
    most the gadget size, so the designer cannot assign counts freely through gates.
(ii) Adversarial numbering: count and the new valuation at v are isomorphism-invariant. The index is used only as a last
    resort, and the run reports how often; on the counters below it fired 0 times unless stated.
(iii) The attack L-SI expects instead: PADDING. count(e) can be raised by hanging dangling Even vertices (priority 0, one
    edge) on v: p dangling vertices add p to the count of every switch at v. A Bland-type counter needs the switch order
    "a_1 before a_2 before ...", i.e. count(a_1) > count(a_2) > ...; but a switch at a_i already changes every vertex
    upstream of a_i, so a_i's count grows with the depth i, and padding must beat the upstream structure of every deeper
    level: on the DLMM counter G_N with pads(i) = 2(N+1-i) the rule still takes 1 iteration (checked 13:20Z). Geometric
    padding would do it but is exponential in size. Whether a polynomial padding scheme exists is the open question; the
    DLMM/Disser-Mosis LargestIncrease bounds (MDPs, probability-scaled) are the analogue to worry about.

## Unproven assumptions, named
- A1: no polynomial-size game makes the count ranking follow a bad fixed order on every visited strategy (the padding
  attack above, generalised).
- A2: the last-resort index tie-break is irrelevant (fires rarely; to be shown insensitive or replaced by randomness,
  which would make the rule Las Vegas and still admissible as M4-R).
