### 5.2 The two gaps
- **E-1 (required; l. 194 and l. 196).** (H2) reads «the input of unit j is (c, c) under s_τ for every τ with t ≤ τ ≤ t + P_j − 1 that
  the run reaches», and the conclusion begins «Then the run reaches s_(t+P_j−1)». If the run has stopped at s_(t−1), (H2) is vacuous

  columns fin 0 (the final state is REST_1(1), REST_i(0)), stuck 0 and e1inst (the instance exists: 1 per k), k = 3..13. The same
  vacuity sits inside the proof: «the run reaches s_τ» is concluded from «a mover is key-enabled», which reads (H2) AT s_τ, and

- **E-2 (required; l. 225-226 «by induction E(j + 1) does not move before step t_1 ≥ t + 2», l. 228-229 «By induction unit j + 1 … make
  exactly the moves of its response in the steps t, …, t_1 … provided its input stays (1, 1), which we check along the way»).** The
  lemma for j + 1 has (H2) on its WHOLE interval [t, t_1] as a hypothesis. At the point where it is used, that hypothesis is not yet
  known: the input of unit j + 1 stays (1, 1) only while u_j does not move, which is shown from EY_j = c, which is shown from «B does

  black box the lemma cannot be applied before its hypothesis holds on the whole interval, so the induction as written is circular.
  The packet's own words («which we check along the way») describe a step-by-step argument; that argument needs the lemma in a
  PREFIX form (the moves of the steps t, …, T follow from the inputs up to T), which is not what is stated. This is the trap this
