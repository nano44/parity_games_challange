# C4: TL×H, tangle learning on the prefix-maximum product game (L-ALG, 2026-10-15 12:05Z)

Status: DEAD on first test (docs/alg/DEAD.md). Honesty note: unlike C1-C3, the pseudocode and the test were produced in the
same hour (experiments/alg/c4_product.py); the running-time claim below was stated before the tc numbers were read.
Idea: the two obstructions so far are complementary: the prefix-maximum product memory lets NE'(1) solve the Two Counters
game tc polynomially (where tangle learning is exponential), and tangle learning solves the sibling-trap compositions S_s,
T_R with O(1)-O(n) tangles (where psolC and its nestings need registers). C4 runs a complete tangle-learning solver on the
product game H instead of psolC: the outer loop of C2 with a complete inner solver.

## 1. Pseudocode
```
C4(G):  A := V; win := undecided
  loop: for p in (0, 1):
          X := P_p(A)
          while X != {}:
            H := H_p(G, A, X)                      # C2.md section 1: states (v, c), entries (x, START), Good sinks for X
            r := TL(H)                             # Oink --tl (van Dijk 2018), complete
            W := {x in X : r(x, START) = p}
            if X ⊆ W: break
            X := X ∩ W
          if X != {}: D := Attr_p(G, A, X); win[D] := p; A := A \ D; restart the loop
        return win
```
Correctness: sound by C2.md section 2 (a complete inner solver is a sound one). Complete: if p wins G from x then x
survives every iteration (p's winning strategy makes its good visits inside W_p ∩ P_p ⊆ X_i), so X* ⊇ W_p(G[A]) ∩ P_p and
Attr_p(X*) ⊇ W_p(G[A]) (every p-won vertex is attracted to a good visit). The outer loop is NOT redundant with a complete
inner solver: a good visit must land on a vertex p actually wins from, which only the fixpoint guarantees (the first
implementation without the loop was wrong on 7 of 30 library games).
## 2. Running time
|H| <= n (d + 1); at most n iterations per player per decision, at most n decisions: <= 2 n^2 calls of TL on games of size
n (d + 1). Unproven claim needed: TL polynomial on the product games H. Expected killer (stated before the test): tc,
if the product does not change the tangle structure of the two counters.
## 3. Result
Killed by tc (section DEAD.md C4): TL's tangle count on H grows x23, x12, x9 per step N -> N+2 (131 / 3,070 / 37,372 /
333,132 at N = 2/4/6/8). The product memory abstracts the counters for a reachability condition, not for tangle learning.
