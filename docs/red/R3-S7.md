## 1. What the rule is (two lemmas, L-RED, unrefereed; both are what L-SI's defence (iii) relies on, made precise)
Call a strategy sigma generic if distinct plays from a vertex have distinct VJ valuations (true whenever no two plays from a
vertex differ only in vertices less relevant than the cycle node and have equal length; in particular in every game without
priority-0 relays). Write up_sigma(v) for the set of vertices whose (sigma, tau)-play visits v.
Lemma T (count = traffic). For an improving edge e = (v, w) of a generic sigma, count(e) = |up_sigma(v)|.
Proof. A vertex x's valuation changes only if its play visits v: plays avoiding v are unchanged, Odd minimises, and by
Friedmann Thm 3.2 nothing decreases, so x's value, the minimum over Odd's routes, is unchanged unless the minimising route ran
through v. If x's play visits v, the old play is gone and every available play is worth at least the old value; equality would
need a different play of the same value, excluded by genericity; so x strictly improves. QED.
Lemma D (downstream dominance). In a generic sigma, if the play of v visits u != v (u is downstream of v), then
up(v) subset up(u) minus {u}, so count(any edge at u) > count(any edge at v). Hence the rule never switches a vertex whose
current play passes through another vertex that has an improving edge; among the improving vertices it chooses a
route-maximal one, and pads (dangling vertices) can only decide between route-incomparable vertices.
Consequences. (a) Within one vertex the count is the same for all its improving edges, so the second criterion (largest new
valuation at v) is the whole rule inside a vertex: S7 = "the most-trafficked improving vertex, switched to its steepest edge".
(b) A counter whose lower bits route through the switching vertex of a higher bit (DLMM G_N, M_L, gated_bland: every
level routes through the levels above) collapses: the top improving bit always wins (G_4 trace: counts 1, 3, 5, 7 for a_1..a_4
at the start; S7 takes 1, 3, 5, ... iterations on these counters). L-SI's padding experiment on G_N fails for this reason and
no padding of G_N can succeed. (c) A killer must keep every "bit" switch off the routes of the other bits: Friedmann's cycle
gates (1106.0778 section 6) do exactly that: the switching vertex d_i of an open or closed gate carries no traffic but its
own pads (open gates are skipped, closed gates are exited at e_i), so pads on d_i set the count of gate i's switches freely
(Lemma D does not bind between gates). The obstacle moves to the correction vertices (s, r, k_i, g_i, the lane), whose
counts are their state-dependent traffic.

The obstruction (Lead reading, from the traces and Lemma D). After bit mu is set and the lower gates have reopened, the
counter needs the lower selectors to move to g_mu (k_j -> g_mu, j < mu) before any reopened gate closes again. The selectors
form a chain: k_{j-1} points into gate j (g_j -> f_j -> e_j -> ...), so k_{j-1} routes through k_j (while gate j's exit is
profitable for Even) or through d_j (once it is not). By Lemma D the downstream vertex moves first: k_{mu-1} updates first,
which makes h_{mu-1}'s route better than d_{mu-1}'s, so Odd at e_{mu-1} turns to d_{mu-1}; every lower selector's traffic now
passes d_{mu-1} and d_{mu-1}'s closing outranks every k_j, j < mu-1. Gate mu-1 closes before the lower selectors update, and
since a gate j < mu-1 cannot close until its own selector has moved, the run sets bit mu-1 next instead of bit 1: the
counter degenerates to a linear sequence. No pad values change this: pads add the same amount to a vertex and to everything
downstream of it. A kill of S7 by a gate counter needs a reset mechanism whose lower selectors are not upstream of the higher
reopened gates (or no selectors at all), i.e. a different spine from Friedmann's; not found in this box. Random search over
per-class schemes alpha + beta (n+1-i) (search_pads.py, 1,000 samples) and hill-climbs from the best scheme reached at most
41 iterations at n = 3 (a working counter needs about 50 and doubling in n), all with the same two-increment prefix.

## 3b. Redesign attempts after the obstruction (box 2, second half)
Gate re-closing argument (L-RED reading, general). In a Friedmann gate, "closable" means Odd at e_i prefers d_i's default route
to the exit, so every play that enters the gate (selectors, roots) passes d_i while the gate is closable; by Lemma D the
closing then outranks every switch of a vertex whose play enters the gate. Hence a reopened gate re-closes before anything
upstream of its entries moves. A counter needs the opposite after a reset: the reopened gates must stay non-closable until
the lower bits have counted up, i.e. the moment at which gate j+1's exit becomes unprofitable (its selector reaching the new
top bit) must come after 2^j further switches. That moment is a selector update whose improvability does not depend on the
lower bits, so no pads fix it, and the two structural changes I tried do not either:
- Split entries (gens_red.friedmann_Gn(split=True)): a second Odd decider e'_i -> {m_i -> s, h_i} for entries from above, so
  that entry traffic never passes d_i. S7 then takes 3n - 1 iterations (n = 2..5: 5, 8, 11, 14): whenever s points at gate i
  (s -> f_i -> e'_i), the branch m_i -> s closes a cycle dominated by the odd f_i, which Odd wins, so Odd always takes it and the
  roots' valuations collapse. Any mimic branch that returns to a root creates such a cycle; a mimic branch that reads the gate
  state must pass d_i (the state IS d_i's edge); a dead-end branch is always Odd's choice. So entries cannot be decoupled from d_i.
- Downward exit chains (exits of closed gates point to the next set bit BELOW, so that Lemma D orders the selectors
  bottom-up, with priorities f_j > h_i for i > j): then s's route always contains the odd f_j of every closed gate j on its
  chain, so Xi(s) prec Xi(e_j) at all times, closed gates are always stable and no reset ever happens (checked on paper;
  not built).
- Stripped gates (d_i -> {e_i, s} only, no lane, no r): same counts as the full game (14, 26, 41, 59): the lane and r are not
  what blocks the counter.
Status: no construction in progress. The precise statement a further box would have to beat: with Friedmann gates, the
selector update that makes a reopened gate closable must be delayed by the lower bits' counting, which requires a selector
whose improvability depends on the lower bits' state while its own traffic (Lemma D) does not outrank theirs.
